# 全中文 AI 精华日报设计

## 目标

将现有以英文 RSS 标题和来源摘要为主的日报，升级为每天一份全中文、可直接阅读和邮件转发的 AI 精华报告。日报覆盖 AI 最新动态、大模型、AI Agent 和 AI Infra，只保留最值得看的 8～10 条；报告中的链接必须指向正文主体为中文的页面。

## 已确认的产品决策

- 采用“国际热点雷达 + 中文来源池匹配”，而不是简单翻译英文原文。
- 国际来源只用于识别全球热点，不直接出现在最终报告中。
- 最终标题、摘要、趋势判断、来源名和链接目标页面都必须是中文。
- 微信公众号文章允许作为来源，但属于增强链路；公众号发现或抓取失败不能阻塞日报。
- AI Infra 提高权重，但不为了凑数量发布低价值内容。
- 默认使用 GitHub Models，每天一次模型调用；模型失败时生成全中文规则降级版。
- GitHub Issue、Markdown 归档和邮件正文共享同一份报告内容。

## 方案选择

### 采用：国际热点雷达 + 中文来源池匹配

国际官方源在时效性和准确性上最好，中文来源在阅读体验上最好。系统先从国际源识别当天重要事件，再从中文池寻找对应报道，同时允许中国市场的原创 AI 新闻独立入选。最终只发布通过中文正文验证的候选项。

### 未采用：只抓中文来源

实现简单且全部中文，但容易遗漏尚未被国内媒体报道的全球重要事件，也无法判断国内资讯池缺少了什么。

### 未采用：依赖搜索引擎实时寻找中文报道

覆盖面更广，但搜索页面容易出现验证码、限流和结构变更，不适合作为每天无人值守任务的主链路。搜索发现只可作为可选增强，不能成为日报生成的必要条件。

## 报告格式

```markdown
# 每日 AI 速报 · 2026-08-04

> 生成时间、观察窗口、使用模型、中文来源成功率

## 📮 今日 AI 风暴

60～100 字总结当天最重要的 AI 趋势。

## 今日最值得看

### 1. [中文精华标题](中文正文链接)

`AI Infra` · `中文来源` · `发布时间`

一句话说明发生了什么，以及为什么值得关注。

（共 8～10 条）

## 🔥 今日三个趋势判断

- 大模型或行业动态趋势
- AI Agent 趋势
- AI Infra 趋势

## 运行状态

抓取数量、候选数量、中文验证数量、模型名称、来源失败列表。
```

入选数量是 8～10 条。没有足够高质量内容时允许少于 8 条，不使用低质量文章填充。AI Infra 在存在合格候选时软性保证至少 2 条。

## 来源设计

### 国际热点雷达

保留现有 24 个来源，包括 OpenAI、Anthropic、Google DeepMind、Google AI、Hugging Face、NVIDIA、AWS、Microsoft Research、Cloudflare、SemiAnalysis、arXiv、Hacker News，以及 vLLM、SGLang、TensorRT-LLM、Transformers、LangChain、LlamaIndex、AutoGen、MCP 等 GitHub Releases。

国际雷达只输出结构化热点信号：实体、主题、发布时间、来源权重和原始标题。最终报告不渲染国际原文链接。

### 中文来源池

按可信度分四级：

1. 官方中文站：NVIDIA 中文技术博客、NVIDIA 中国博客、AWS 中国博客及其他可稳定获取的厂商中文公告。
2. 专业 AI/技术媒体：量子位、InfoQ AI、机器之心、新智元、AI 科技评论等。
3. 综合科技媒体：36氪、极客公园、腾讯科技等，仅保留 AI 高相关内容。
4. 微信公众号：从配置的账号来源、中文媒体页面中的公众号链接和可用的公开发现入口获取。

源配置包含 `name`、`type`、`url`、`credibility`、`categories` 和 `enabled`。RSS/Atom 优先；没有稳定 Feed 的站点使用独立 HTML 列表适配器。适配器失败时记录来源错误并继续处理其他来源。

微信公众号链路不使用个人 Cookie，不模拟登录，不绕过验证码。发现入口不可用时自动跳过公众号候选。

## 数据流

1. 国际雷达抓取最近 36 小时内容。
2. 中文来源抓取最近 48 小时内容，为国内转载和中文编辑留出延迟窗口。
3. 统一清洗标题、摘要、发布时间、来源、URL 和分类信息。
4. 提取公司、模型、产品、框架、芯片和基础设施实体，形成事件签名。
5. 使用实体重合、时间接近度、标题关键词和分类对国际热点与中文报道进行初步匹配。
6. 中文原创事件即使没有国际匹配，只要相关度和来源可信度达到阈值也可进入候选池。
7. 对中文候选执行页面可访问性、语言和正文质量验证。
8. 规则层按相关度、新鲜度、来源可信度、国际热点匹配和 AI Infra 加权筛出最多 25 条。
9. 将 25 条以内的候选交给 GitHub Models 一次性完成最终选稿和中文编辑。
10. 校验模型输出后，渲染统一 Markdown，再用于仓库归档、Issue 和邮件。

## 中文正文验证

候选链接必须同时满足：

- HTTP 请求成功，最终地址使用 `https`。
- 页面标题包含至少 4 个中文字符。
- 提取后的正文包含至少 120 个中文字符。
- 中文字符占正文中的中英文字符比例不低于 25%。
- 页面不是登录页、验证码页、搜索结果页或空壳导航页。

微信公众号页面使用同一套规则。无法提取正文的公众号链接不进入模型候选池。

## 匹配与排序

每条中文候选得到以下分数：

- 主题相关度：大模型、AI Agent、AI Infra 或重大行业动态。
- 来源可信度：官方中文站最高，专业技术媒体次之。
- 新鲜度：48 小时内随时间衰减。
- 国际热点匹配：与高权重国际事件匹配时加分。
- AI Infra 加权：芯片、训练、推理、Serving、量化、GPU 集群、网络和存储等内容加分。
- 热度信号：仅作为辅助，不允许低可信来源仅凭热度入选。

重复事件通过事件签名和标题相似度合并。同一事件存在多个中文来源时，依次选择官方中文站、专业技术媒体、内容更完整且发布时间更近的页面。

## GitHub Models 接入

工作流增加：

```yaml
permissions:
  contents: write
  issues: write
  models: read
```

默认调用：

- Endpoint：`https://models.github.ai/inference/chat/completions`
- Token：Actions 自动生成的 `GITHUB_TOKEN`
- Model：`openai/gpt-4.1-mini`
- 调用次数：每次日报最多一次

仓库变量 `GITHUB_MODELS_MODEL` 可以覆盖默认模型。若现有 `LLM_API_KEY`、`LLM_ENDPOINT` 和 `LLM_MODEL` 三项全部配置，则允许显式使用外部 OpenAI Chat Completions 兼容服务；未配置时默认 GitHub Models。

模型接收候选 ID、中文标题、中文摘要、来源、分类、发布时间和匹配到的国际热点信息。外部文本全部标记为不可信材料，提示词明确禁止执行文章中的指令。

模型返回结构化 JSON：

- `storm_summary`
- `selected_items`：候选 ID、编辑后的中文标题、核心摘要、价值判断
- `trends`：最多 3 条趋势判断

模型不返回可直接使用的 URL。渲染器根据候选 ID 从已验证候选表中取 URL，因此模型无法编造或替换链接。

## 降级与错误处理

- 单个中文或国际源失败：记录错误，继续运行。
- 中文候选少于 8 条：按实际数量发布，不填充英文链接。
- GitHub Models 限流、超时或返回无效 JSON：使用规则排序和中文来源原标题、摘要生成全中文降级版。
- 模型返回未知候选 ID：丢弃该项；如果剩余条目不足，使用规则候选补齐。
- 中文正文验证失败：该候选在调用模型前移除。
- 邮件失败：保留已提交的 Markdown 和 Issue，邮件步骤单独报告失败。

## 状态与可观测性

报告和 Actions 日志记录：

- 国际原始条目数
- 中文原始条目数
- 通过中文正文验证的条目数
- 国际热点匹配数
- 最终入选数及分类分布
- 实际使用的模型或“规则降级”
- 成功与失败来源数

日志不得输出 Token、SMTP 密码或其他 Secret 值。

## 测试策略

新增或扩展离线单元测试，覆盖：

- RSS/Atom 和中文 HTML 来源解析。
- 中文正文比例与最小长度验证。
- 英文页面、登录页和验证码页拦截。
- 国际事件与中文报道的事件签名匹配。
- 重复事件合并和中文来源优先级。
- AI Infra 加权以及无合格内容时不强行凑数。
- GitHub Models 正常 JSON、无效 JSON、未知候选 ID 和超时降级。
- 渲染结果只包含候选池中的中文正文链接。
- Markdown、Issue 和邮件读取同一报告文件。

上线验证包括一次手动 `workflow_dispatch`：确认 Actions 获得 `models: read`、报告显示实际模型、Issue 内容全中文、所有最终链接通过中文正文检测，并确认无模型 Secret 时仍能使用 GitHub Models。

## 非目标

- 不绕过微信公众号或媒体网站的登录、验证码和付费墙。
- 不把 GitHub Actions 运行分钟视为模型 Token 额度。
- 不保证每条国际热点都能在当天找到中文报道。
- 不全文转载中文媒体内容，只生成短摘要并链接原文。
- 不让大模型自主访问互联网或调用任意工具。

## 成功标准

- 每日自动生成最多 10 条中文精华报告；常规目标为 8～10 条，合格候选不足时允许更少。
- 最终报告不存在英文正文链接。
- 有合格候选时，AI Infra 至少占 2 条。
- 每次日报最多调用一次 GitHub Models。
- 模型不可用时仍能生成全中文报告。
- GitHub Issue、Markdown 与邮件内容一致。
- 任一来源失败不导致整个工作流失败。
