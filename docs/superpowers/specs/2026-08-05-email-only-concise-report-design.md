# 邮件专用精简 AI 速报设计

## 目标

把每日 AI 速报调整为适合在手机邮箱中快速阅读的版本，并停止创建 GitHub Issue。每条资讯保留足够的判断上下文，但移除重复和占空间的内容。

## 最终内容格式

报告保留日期、“今日 AI 风暴”总览和“今日精华”列表。每条资讯统一呈现为：

```markdown
1. [可点击的精炼中文标题](已验证的中文正文链接)

   `AI Infra` · `08-05 09:27`

   一段简短中文介绍。
```

具体规则：

- 标题必须直接链接到已验证的中文正文，最长 35 个可见字符。
- 标签只保留分类和发布时间，不显示量子位、InfoQ、NVIDIA 等媒体或站点名称。
- 每条保留一段短介绍，说明发生了什么；不追加第二段解释。
- 完全删除“为什么值得看”。
- 每期最多 10 条，高质量候选不足时不凑数。
- 抓取、筛选、模型和来源异常只进入 Actions 日志，不混入报告正文。

## 生成与存档

现有中文来源抓取、链接校验、候选排序、模型精编和规则降级流程保持不变。生成结果继续写入：

- `reports/latest.md`
- `reports/YYYY-MM-DD.md`
- `reports/latest.json`
- Actions artifact

Markdown 存档与邮件必须使用同一组资讯、标题、分类、时间和短介绍，避免两个版本内容不一致。

## 邮件发送

邮件同时包含纯文本和 HTML 两种正文：

- 纯文本部分使用 Markdown 报告，兼容不支持 HTML 的客户端。
- HTML 部分将标题渲染成真正的超链接，并用适合手机阅读的间距显示标签和短介绍。
- HTML 中的标题、链接、标签和介绍全部经过转义或受控转换，不能注入任意 HTML。
- 邮件主题保持 `每日 AI 速报 · YYYY-MM-DD`。
- 原有 Markdown 附件继续保留。

SMTP 成为唯一通知渠道。工作流必须执行邮件发送步骤；如果缺少必需的 SMTP Secret 或发送失败，任务应明确失败并显示缺失的配置项，但不得输出 Secret 内容。

## 停用 GitHub Issue

- 从 Actions 工作流中移除每日 Issue 创建步骤。
- 移除 `issues: write` 权限，只保留报告归档所需的 `contents: write`。
- 不再使用 `CREATE_DAILY_ISSUE` 变量。
- `src/publish_issue.py` 可以暂时保留为历史工具，但定时和手动工作流都不得调用它。

发布到 `main` 后，原有定时任务会直接运行新代码，不创建第二套定时工作流，因此旧发送版本自然停止。

## 错误处理

- 未配置 SMTP：邮件步骤失败，并列出缺失的环境变量名称。
- SMTP 登录或投递失败：邮件步骤失败，Actions 保留错误类型供排查。
- 报告为空：仍发送包含日期和“本期没有筛出足够可靠的中文 AI 资讯”的邮件。
- 邮件失败不回滚已经生成的仓库报告和 artifact。

## 测试标准

- 报告包含可点击标题、分类、时间和短介绍。
- 报告不包含来源名称或“为什么值得看”。
- HTML 邮件中的标题是可点击链接，特殊字符被正确转义。
- 邮件同时具备纯文本、HTML 和 Markdown 附件。
- 工作流不再请求 Issue 写权限，也不调用 Issue 发布脚本。
- 缺少 SMTP 配置时给出清晰错误；配置完整时调用正确的 SSL 或 STARTTLS 流程。
- 完整测试套件通过，并能在本地生成一份真实格式预览。
