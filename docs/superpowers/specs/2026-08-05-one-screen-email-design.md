# 一屏 AI 标题邮件设计

## 目标

让收件人在手机邮箱中不滚动或只需极少滚动，就能浏览当天全部精选 AI 资讯，并通过标题直接打开中文原文。

## 最终正文

邮件和 Markdown 报告统一只包含最多 10 条编号链接：

```markdown
1. [精炼中文标题](中文正文链接)
2. [精炼中文标题](中文正文链接)
3. [精炼中文标题](中文正文链接)
```

正文不得出现：

- “每日 AI 速报”和日期标题；
- “今日 AI 猛料”或其他总览；
- 分类、来源和发布时间；
- 摘要、内容介绍和“为什么值得看”；
- 运行状态、错误信息或说明文字。

标题继续由现有模型编辑或规则降级流程精炼，并直接链接到已验证的中文正文。标题不得按固定字数截断或添加省略号；模型应输出简洁但语义完整的标题。候选不足时按实际数量发送，不凑数。

## 邮件结构

- 邮件主题保留 `每日 AI 速报 · YYYY-MM-DD`，便于在收件箱检索和区分日期。
- HTML 是主要正文，只渲染紧凑的编号标题列表。
- 邮件保留同内容的纯文本兼容层，以支持禁用 HTML 的客户端；纯文本不是附件。
- 删除 Markdown 附件，邮件不得出现附件图标或附件区域。
- HTML 标题与 URL 必须转义，避免不可信内容注入标签或属性。
- 手机端正文最大宽度 680 像素，使用 14 像素标题字号、1.35 行高、每条上下 5 像素间距和紧凑分隔线。完整长标题允许自动换行，优先保证 10 条能在一页左右浏览。

## 空结果

当天没有合格资讯时，正文只显示“本期没有筛出足够可靠的中文 AI 资讯。”，不显示标题、日期或总览。

## 不变范围

抓取、中文链接校验、去重、排序、模型精编、每日最多 10 条、仓库归档、Actions artifact、SMTP 收件人和抄送配置保持不变。GitHub Issue 继续停用。

## 测试标准

- 非空报告只包含编号 Markdown 链接。
- 报告中不存在日期标题、总览、标签、时间、介绍、来源和“为什么值得看”。
- HTML 正文只包含同样数量的可点击标题，不渲染额外文字。
- HTML 对标题和 URL 中的特殊字符进行转义。
- 邮件包含纯文本与 HTML 正文，但没有任何附件。
- 最多显示 10 条，未知候选 ID 不能注入链接。
- 空结果正文只有一行说明。
- 完整测试套件通过，并输出一份 10 条标题的手机宽度 HTML 预览供检查。
