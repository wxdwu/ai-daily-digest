# 精致的一屏 AI 邮件设计

## 目标

在手机邮箱中用一屏左右读完当天最多 10 条中文 AI 标题。邮件需要比默认链接目录更有编辑感，同时保留完整标题、中文正文链接和紧凑阅读效率。

## 截图审视

当前版本已经做到 10 条标题一屏展示、链接完整可点，这是应保留的核心。主要问题是所有标题都使用默认蓝色下划线，视觉权重相同；默认有序列表缺少明确的内容入口；英文词被 `word-break: break-all` 从中间拆开，降低扫读体验。

## 选定方向

使用“动态焦点标题 + 紧凑标题清单”，不做分类分组，也不恢复摘要、标签、来源、时间和附件。

邮件正文结构：

1. 顶部是一块高度受控的浅蓝焦点区。
2. 小字显示 `AI DAILY · N 条精选`。
3. 主标题显示模型或规则生成的当日内容焦点，控制为 14～24 个中文可见字符，不使用“猛料”“一页看完”等模板化口号。
4. 下方继续显示最多 10 条完整可点击标题。

## 视觉规格

- 正文最大宽度 680px，白色背景，手机端左右留白 14px。
- 焦点区使用极浅蓝背景、3px 蓝色左边线、8px 内边距；主标题 15px、700 字重。
- 列表标题使用 14px、1.35 行高、600 字重和深蓝灰链接色。
- 每条上下内边距 5px，用极浅分隔线区分。
- 链接不显示默认下划线，但保留深蓝色作为可点击提示。
- `overflow-wrap: anywhere` 只在确实溢出时断行；`word-break: normal` 避免 SpaceX、Kubernetes 等英文词被任意拆开。
- 关键样式同时写入元素内联样式，优先兼容会改写 `<head>` CSS 的手机邮件客户端。

## 内容与数据流

- 模型编辑继续只调用一次；`storm_summary` 改为 14～24 字的当日焦点标题。
- 未配置模型时，由规则根据入选分类生成简短焦点标题，例如 `大模型与 AI Agent 成为今日焦点`。
- Markdown 和纯文本邮件第一行写焦点标题，空一行后写编号链接列表。
- HTML 解析第一行作为焦点标题，其余 Markdown 链接渲染为紧凑列表。
- 当天没有合格资讯时，保持现有单行空结果提示，不渲染空焦点区。

## 安全与兼容

- 焦点标题、文章标题和 URL 全部 HTML 转义。
- 文章链接仍仅接受现有 `https://` Markdown 格式。
- 邮件继续使用 `multipart/alternative`，不发送附件。
- 邮件主题和 SMTP 配置保持不变。

## 验收

- 有内容时 HTML 恰好包含一个焦点标题和最多 10 条可点击完整标题。
- 不出现标签、来源、时间、介绍、“为什么值得看”或附件。
- 标题链接无默认下划线，长英文优先按单词换行。
- 10 条典型标题在手机宽度预览中保持一屏左右的密度。
- 全量自动化测试通过，随后推送 `main` 并手动触发 GitHub Actions；只有工作流和邮件步骤成功后才交付。
